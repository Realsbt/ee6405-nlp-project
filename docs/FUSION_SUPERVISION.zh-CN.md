## 第三批的独立问题

- 架构：有意义的 EDU 边界是否优于不依赖 parser 的固定 token 块？
- 训练：同一文本的随机 dropout 预测是否应保持一致？

四组均保留 CLS、相同注意力/门控/分类头、同一正文、同样 CE 采样与基础预训练
初始化。每个训练 batch 都做两次前向，CE 为两次 CE 的均值，避免把双前向
预算当作一致性约束的效果。仅一致性组额外加入权重 1 的对称 KL：

```text
L = (CE(p1,y) + CE(p2,y))/2 + lambda * (KL(p1||p2)+KL(p2||p1))/2
lambda = 0 或 1
```

本方法不需要跨文本/来源配对，也没有把原文和编辑版视为已知。它是已有
dropout 一致性思想在本项目上的对照实验，不声称发明该训练方法。
部署/评估每篇只做一次前向，额外训练成本单列。

固定块排除 BOS/EOS/padding，每块最多 32 个 body tokens，末块可短。
模型前向不读取 EDU 边界；离线训练仍复用了已生成的缓存和索引，所以不能
把此前解析开销从项目总成本中抹掉。新原文的完整推理适配尚需单独验收。

## 开发与校准隔离

第三批在训练前按 source group 的固定 SHA256 排序，把原 validation 分成
selection/calibration 两半。checkpoint 只使用 selection；calibration 不参加
每轮评估、早停和选型。每次保存两半 ID、组 ID 及哈希，原 test 不变。
两半都必须含四类，否则拒绝静默运行或根据模型效果换分区。

最终保存完整 validation 预测供重放与校准，但不得用 calibration 的表现
返回修改该批模型。原始 HART 及部分测试结果已有历史开发接触，因此这个隔离
只保护本批拟合流程，不把旧数据重新包装为从未见过的独立验证。

第一/二批已用完整 validation 选模，不能事后切一半便声称独立校准。
第三批与前两批的开发规则不同，主结论来自第三批内部匹配对照。
