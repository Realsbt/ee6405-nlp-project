# 项目复盘、研究架构与 GPU 交接

日期：2026-11-06。依据本组归档结果、此次CPU实测与用户提供的结果表。已完成的是本轮明确执行的复核、来源匹配、外部测试、重放与校准；不是整个论文或全部消融已经完成。本文不按人数分工。

## 一句话判断

原项目已经有可运行的复现与模型比较基础，但还没有充分回答“篇章结构是否真正提供额外信息，以及这种信息能否跨编辑场景保持有效”。这轮工作的贡献主要是补齐证据和发现边界，不是发明了一个新的高分模型。下一轮GPU预算应优先用来回答机制与泛化问题。

## 1. 原来的问题究竟是什么

### 不是所有工作都没有差距

用户图中的90%左右是Macro-F1，不是accuracy。TF-IDF的79.40%与最好的神经配置91.15%之间已有11.75个百分点差距；已有实验说明预训练文本表征在这份数据上有明显优势。

真正需要解释的是神经方法之间的差别：

| 图中比较 | Macro-F1差值，百分点 | 可以说什么 |
|---|---:|---|
| RoBERTa加SupCon：90.72→91.15 | +0.43 | 本协议下有小幅平均增益 |
| RACE加SupCon：89.92→90.37 | +0.45 | 同样有小幅平均增益 |
| RACE CE相对RoBERTa CE | -0.80 | 复杂结构方法在该配置下未优于文本基线 |
| RACE+SupCon相对RoBERTa+SupCon | -0.78 | 不能把RACE写成这组实验的最佳方法 |

差值由截图四舍五入值计算。不能只凭均值和标准差判断显著性，也不能因差异小就宣布等价、无效或数据已经达到上限。应看配对种子差值、来源组区间和不同测试条件。

### 主要缺口

1. **问题与表格没有完全对应。** 比较谁的F1更高，不能单独证明creator/editor机制或篇章关系的作用。
2. **模型比较存在混杂。** 现有RACE词汇窗口为前512 tokens，但保留全文图结构；它与RoBERTa还同时改变了pooling、参数量和计算成本。仅看差值不能把结果归因于图。
3. **标签含义容易被过度解释。** `ai_humanized`包含工具与真人改写，不能直接称为“AI创作、真人编辑”；分类标签不等于恢复完整历史编辑过程。
4. **域内高分不足以说明外部有效。** 新增MixSet保守子集上，RoBERTa CE3407从HART的0.9075降到0.3901。这个子集有359条、91来源组，存在映射与规模限制，但足以提示值得严查迁移问题。
5. **总体排序分数不等于实用操作点。** 四分类Macro-AUROC、四分类Macro-F1和AI creator二分类的低误报召回是不同指标，不可混写。HART验证集选出的经验1%FPR阈值，在外部集不保证1%FPR。
6. **交付链有缺口。** 有保存预测不等于有可恢复checkpoint；Release仍缺后补的5份权重。论文、视频和实际运行环境也需要分别验收。

这些是本组协议的局限，不是据此认定原论文造假或图模型普遍无效。原论文明确提出RST/EDU的creator-editor建模，来源见[RACE原论文](https://aclanthology.org/2026.acl-long.235/)；本组新增机制对照尚未执行，不能把待检验解释写成事实。

## 2. 这轮实际做了什么

以下可以作为工作记录，但应如实说明使用了代码/工具辅助，不写成已经亲自人工标注全部样本或设计了新算法。

| 工作 | 实际完成 | 学术意义与边界 |
|---|---|---|
| 原实验复核 | 13组HART、4组HC3保存结果一致性检查 | 排除表格与保存预测不一致，不等于验证原作者身份 |
| 来源审计 | 15,984条保留HART样本全部与原始元数据匹配；humanized中765条工具、250条真人 | 澄清真值含义；仍非独立核查真实创作历史 |
| 外部数据 | 冻结MixSet保守映射子集，完成TF-IDF/RoBERTa推理和来源组bootstrap | 增加编辑迁移证据；不是标准MixSet完整benchmark |
| 低误报评测 | 验证集锁阈值，测试报告实际FPR/TPR | 不再用测试集选一个漂亮阈值冒充部署表现 |
| 模型复现 | 恢复parser和权重；RACE HART3194条、HC3重新解析1000条均重放通过 | 原分类结果可在macOS CPU复现；只覆盖指定配置与种子 |
| 概率校准 | TF-IDF、RoBERTa CE3407、RACE CE+SupCon3407验证集温度校准 | 有些概率误差改善，外部失败仍在；没有重新训练 |
| 工程与研究记录 | 31项单元测试、资源哈希、协议、文献核验与交接文档 | 支撑复核和后续实验；不自动构成算法创新 |

关键负结果：RACE校准后在HC3的Brier为0.43802，仍高于恒定0.5概率的0.25；验证集锁定低误报阈值下，实际FPR为3.2%，TPR仅1.2%。这不是“检测器已经可靠”，而是明确的迁移限制。

证据位置：`03_CPU执行结果.md`、`08_RACE重放与验证集校准.md`、`cpu_calibration_completed_v1.json`。RACE的MixSet推理尚未运行；不能把两种模型的外部结果写成三种模型都已完成。

## 3. 有GPU资源的人具体做什么

### 启动前：不是收到清单就立刻开训

目前parser和基础数据已恢复，但同窗口全量图缓存、新控制条件和留域训练入口仍待实现。不能声称只缺一张GPU或已经有一键启动全部实验的脚本。

先完成CPU可做的前置项：同窗口截断与重新解析、控制图构造、分组隔离、输入一致性测试、有限梯度检查。训练机核对依赖、模型版本、资源哈希；只用train/dev样本做smoke和显存检查。

### GPU优先队列

| 优先级 | 任务 | 运行预算 | 必须回答的问题 |
|---|---|---:|---|
| 0 | 找回缺失权重并验证原训练环境 | 不必重新训练 | 能否复用原实验、避免重算？ |
| 1 | 同窗口：文本基线、正常RST图、关系置换图、无GNN的EDU pooling；固定CE | 4条件×3种子=12 | 图关系是否超出文本/切分/聚合带来增益？ |
| 2 | RoBERTa+SupCon与RACE+SupCon留一领域测试 | 2模型×4目标域×3种子=24 | 目标领域完全未参与开发时能否泛化？ |
| 3 | 公平窗口下复核SupCon，再选择一个不同原理基线 | 先冻结配置再定预算 | 增益来自结构、训练目标，还是通用检测信号？ |

第二阶段是明确的候选确认方案，不应训练完四个域后只挑一个有利域报告。若因预算改变模型、种子数或域数，应在新测试前记录修改原因与新协议，不能偷偷缩减。

不先给硬件小时数或显存承诺：训练机尚未做实际profile。可以用固定train/dev smoke测每epoch时间与峰值显存后估算，不要拿本机CPU推理时间估GPU训练成本。

### 必须交回的产物

每次运行交回：配置、代码commit及哈希、数据/缓存哈希、种子、环境、开发集曲线、选模记录、best checkpoint及SHA、逐样本logits/概率、测试指标、训练时间/显存/解析成本、失败记录。不要只交一张高分截图。

缺失权重为RoBERTa+SupCon三个种子，以及RACE CE的42/2026；应先从原训练资源目录找回，不能用别的配置权重冒充。详见06与07。

## 4. 应该有的研究架构

建议主问题：

> 在来源组隔离、相同可见正文和固定低误报阈值下，篇章关系能否提供独立于文本表征与EDU聚合的增益？这种增益能否跨领域与编辑过程保留？

研究流程：

```text
原始文本 + 可追溯creator/editor/operation元数据
    -> 标签审计、重复关联与来源家族构建
    -> 按来源组隔离 train / dev / calibration / test
    -> 固定文本窗口和parser，缓存版本化
    -> 统一条件下的模型与机制对照
    -> dev选模；calibration拟合温度和阈值
    -> 冻结后评测：
       域内四分类 / 留域 / 编辑迁移 / creator二分类
    -> 成组不确定性、种子稳定性、成本与错误分析
    -> 可重放资源包 + 论文/展示
```

这是下一轮应采用的目标流程，不表示当前已有独立calibration分区。当前温度拟合复用了参与checkpoint选择的验证集，需要披露。

这套架构不需要先建一个大而全的新benchmark。先使用现有可兼容的数据，只有来源、编辑者和编辑强度的受控比较确实缺失时再建小型配对研究集。LLM裁判可辅助评价语义保持和文本质量，不能生成creator/editor来源真值；目前没有调用裁判API。

## 5. 应该有的模型架构

建议先做可替换模块的实验架构，不急着新增多头融合大模型：

```text
相同可见正文（同一tokenizer、同一512-token预算）
    -> 共享规格的RoBERTa编码器 -> token表示
       A: 文本pooling ----------------------+
       B: 可见正文EDU + RST图 -> RGCN -------+-> 统一规格投影/分类头
       C: B的逐图关系置换控制 ---------------+        -> 四类概率
       D: 同EDU切分 -> EDU pooling，无GNN ---+
```

A/B/C/D是分别训练的对照条件，不是默认全部拼接后联合训练的四分支网络。复用同一基础预训练revision、训练预算、损失、选模规则；报告各自参数量，不把统一分类头等同严格等容量。

四类输出保留：

- human_written；
- human_ai_polished；
- ai_generated；
- ai_humanized。

AI creator分数可直接由后两类概率相加得到，不必为展示额外训练一个head。现有标签不能无条件拆成“人/AI创作者 × 人/AI编辑者”二乘二，因为humanized含工具改写，且有未编辑的类别。

只有机制实验显示某个模块有稳定价值，才考虑门控融合、creator辅助监督或其他新架构，并单独验证其增益。模块堆叠或多任务本身不自动构成新颖性。

## 6. 怎么判断下一步结果

| 观察 | 合理解释与下一步 |
|---|---|
| 正常图稳定优于EDU pooling及关系控制 | 支持结构信息有贡献；再看跨域是否保留，仍需排除容量等残余混杂 |
| 图不优于EDU pooling | 简化模型，讨论切分/聚合是否足够；不再把所有增益归因于关系 |
| 同分布有增益，留域消失 | 贡献重点转向泛化限制与结构信号的域依赖 |
| F1差别小，但低误报召回/成本有稳定优势 | 用预先确定的指标论证实际收益，不事后更换主指标掩盖负结果 |
| 不同种子结论不一致 | 报告不确定性，检查优化、数据支持数与parser质量，不挑最好种子 |
| 所有对照都无优势 | 允许严谨的负结果；不能为发表强行制造一个胜出的新模型 |

## 7. 论文应有的组织

1. Introduction：为什么区分原始创作者与后续加工，为什么高域内分数仍不足够。
2. Task and Data：四类的操作定义、来源证据、来源组隔离、外部映射及限制。
3. Methods：文本基线、篇章模型、训练目标和公平控制条件。
4. Evaluation Protocol：开发/校准/测试隔离、四分类与二分类赛道、低误报规则、不确定性。
5. Results：域内主表、机制消融、留域/外部迁移、校准与成本。
6. Discussion and Limitations：结构是否有用、哪些场景失效、标签/样本/协议限制。
7. Reproducibility and Ethics：代码与权重、资源许可、不能用于无依据指控作者、工具使用披露。

这是一篇研究论文的建议组织，不替代课程要求。课程交付还要依据正式要求补齐报告、演示材料、视频及个人声明。

## 可直接向组员说明

“原来的实验不是没价值，它已经建立了复现和模型比较基础。但现在神经模型都在90%左右，复杂RACE还没超过RoBERTa，这张表不能说明图结构到底有什么贡献。我这轮借助工具补了来源审计、checkpoint重放、外部测试、低误报评测和校准，发现域内高分到外部编辑场景会明显退化。接下来GPU资源优先用于同窗口机制消融和留域实验，不再只围着原测试集调零点几个百分点。最后要交付的是有证据的机制与泛化结论，而不只是更高的一行数字。”
