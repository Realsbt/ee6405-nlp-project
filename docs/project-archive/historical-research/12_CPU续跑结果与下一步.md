# CPU续跑：结果、失效定位与下一步

日期：2026-11-09。承接“梳理 EE6405 无 GPU 项目任务”的中断实验。没有新训练神经模型，没有在MixSet上选参数/阈值，没有登录云账号、上传数据或修改原仓库源码。

最终状态见`13_同窗口消融实现与CPU验收.md`：截至2026-11-11，四条件模型/训练入口、v3全量15,984条图缓存、全量控制审计和CPU反向均已完成；正式12次GPU消融尚未运行。本文以下“尚未实现”的描述保留为本阶段历史记录。

## 1. 当前最重要的判断

**CPU确实可以提高域内分数；但域内融合收益并未迁移到外部编辑场景。现在更值得研究的是信号的可迁移性与creator/editor混淆，而不只是增加模型复杂度。**

| 方法 | HART测试Macro-F1 | MixSet子集Macro-F1 | 状态 |
|---|---:|---:|---|
| RoBERTa CE3407 | 90.75% | 39.01% | 既有固定基线 |
| RoBERTa SupCon3407 | 91.43% | 未评 | 外部推理仍缺对应权重 |
| RACE SupCon3407 | 90.84% | 33.38% | 本轮补齐外部推理 |
| CE与RACE固定概率融合 | 92.10% | 36.86% | 本轮补齐外部推理 |
| CE+TF-IDF Stacking | 92.91% | 37.58% | 前一对话留下的固定对照 |
| CE+RACE+TF-IDF Stacking | 93.61% | 36.22% | 本轮补齐外部推理 |

这是**同一底层种子3407的结果**，不是三次独立训练的均值。Stacking使用开发集来源组4折OOF选元模型，再在完整开发集拟合；底层checkpoint已用过完整开发标签，因此OOF不是完全独立确认。

前一对话留下的“底层种子42/2026”列只是把神经预测换成其他种子、保持3407元模型不变，不能称为三次独立Stacking训练。旧测试集也已被前期分析使用，本轮是后验补充评测。

## 2. 本轮实际补齐什么

### RACE及已有融合的外部对照

- 原问题：MixSet表缺RACE，无法判断篇章模型及包含它的融合是否更能迁移。
- 方法：359条/91来源组全部重新CPU解析，检查原文保持、顺序跨度和非空白字符覆盖；加载固定RACE checkpoint；沿用HART开发集校准、阈值及已保存元模型。
- 结果：359条覆盖全部通过；解析约155.16秒、parser加载20.72秒，RACE预处理/推理约26.27秒。这不是独占硬件的正式benchmark。
- 结论：RACE外部Macro-F1为33.38%，相对RoBERTa CE差-5.63个百分点，固定模型来源组95%区间[-9.50,-1.89]。三模型Stacking为36.22%，相对CE差-2.79个百分点，区间上界约+0.0007个百分点，不能夸大为严格显著退化。
- 低误报：HART开发集经验1%FPR阈值迁移后，RACE的实际FPR/TPR为13.60%/5.50%；三模型Stacking为18.80%/5.50%。这里负类含所有人类creator文本，不只是未编辑的人类原文。
- 限制：来源组区间不包含训练/选择/阈值拟合不确定性，未校正多重比较；保守映射子集不是MixSet完整基准；RACE仍使用全文图，不是同窗口消融。
- 证据：`external_completed_cpu_v1/REPORT.md`、`results.json`、`parse_coverage.json`及逐样本概率。

### 轻量结构算法的测试补全

- 原问题：此前只跑了开发集，不知道简单结构是否值得继续投入。
- 方法：不重训，使用已保存的长度、结构、组合LR模型和开发集固定融合系数；全量HART测试与同一MixSet子集评测。
- 结果：

| 特征 | HART测试Macro-F1 | MixSet子集Macro-F1 |
|---|---:|---:|
| 长度 | 42.41% | 35.06% |
| 结构 | 44.27% | 23.95% |
| 长度+结构 | 52.67% | 29.16% |

- 结论：长度+结构在HART比长度单独高10.26个百分点，条件区间[8.49,11.95]；在MixSet反而低5.91个百分点，区间[-11.28,-0.76]。支持“这些统计量包含域内预测信息，但当前简单实现不够稳健”的判断，不支持把该模型宣传为更强检测器。
- 限制：全文结构包含长度/领域代理；不是纯关系语义消融。HART沿用发布图，MixSet采用本机固定parser，仍有解析管线差异。开发选结构融合权重为0，本身就是不采用该分支；不能把它视为结构带来增益。
- 证据：`structure_completed_cpu_v1/REPORT.md`与`results.json`。

### 同来源原文—编辑版配对分析

- 原问题：外部失效究竟主要出现在编辑后，还是原文已经不被识别？
- 方法：每个来源绑定唯一原文和编辑版本。来源内先平均编辑版本，再对来源等权统计，避免四个变体的来源比一个变体的来源权重更大；无拟合或阈值修改。
- 结果：人类来源50组/200编辑版，AI来源41组/68编辑版。

| 模型 | 人类来源误报：原文→AI润色后 | AI来源召回：原文→人工改写后 |
|---|---:|---:|
| RoBERTa CE | 12.00% → 29.50% | 19.51% → 18.29% |
| RACE | 4.00% → 40.00% | 9.76% → 19.51% |
| 三模型Stacking | 12.00% → 32.50% | 12.20% → 13.41% |

上述为creator分数阈值0.5下的来源平衡比例，不是低误报操作点。对应RACE人类来源平均AI分数从0.074升到0.406，配对差+0.332，来源组区间[+0.241,+0.418]。

- 更具体的错误：68条人工改写AI文本中，RACE有56条被判为human_ai_polished，ai_humanized召回为0；RoBERTa有57条落入human_ai_polished，仅1条判为ai_humanized。
- 结论：**不能把失效全部归因于人工改写抹去痕迹，因为未编辑AI原文本身也已严重失效。** 人类原文经AI润色后的creator误报又明显增加，值得检查模型是否依赖表达风格、生成器或数据来源的代理信号。
- 限制：这不是随机编辑试验，不证明某个组件的因果作用，也不能单凭此认定数据标签错误。表达风格捷径仍是待验证假设。
- 证据：`edit_pair_diagnostics_cpu_v1/REPORT.md`、`results.json`。

## 3. 同窗口准备的进展

新增`prepare_same_window_cpu.py`，只读取train/dev，按4领域×4类别每格1条选择，每个分区16条，共32条：

1. 用同一tokenizer形成不超过512个含特殊符号token的可见正文；检查前缀重新分词的边界变化。
2. 对该可见正文重新解析，不剪裁原全文树。
3. 检查解析字符覆盖、模型token完全相同、EDU token spans有效、无隐藏EDU、train/dev来源组隔离。

第一轮严格对齐31/32成功，最后一条`writing-test11041_ai_humanized_tool`触发非空白字符不一致。失败输出和日志完整保留，未跳过样本：`resources/experiments/same_window_smoke_v1/failure.json`。

为验证是否只是Unicode兼容等价，新增独立、显式启用的`parse_nfkc_cpu.py`适配：

- 先尝试原严格匹配；失败才比较NFKC规范化后的完整非空白内容。
- 不修改原文或模型输入，不忽略标点差异；只有兼容规范化等价才映射回原字符。
- 如果EDU边界切开单个原字符的规范化展开，或存在无法表示的跨字符组合，则拒绝。
- 适配只在研究脚本运行时启用，不修改原仓库或已归档的解析/重放结果。

第二轮**32/32全部通过**，train/dev各16条，覆盖遗漏与隐藏EDU均为0，模型token与可见正文完全一致、来源组隔离。仅1条使用了严格验证的NFKC兼容映射，其余31条沿用严格匹配。解析约36.84秒，加载约20.03秒。结果见`resources/experiments/same_window_smoke_nfkc_v2/verification.json`和`parsed.audit.json`。

它仅是小样本输入/解析检查，不等于全量缓存、四条件模型或训练已就绪。

## 4. 接下来按什么路径推进

| 优先级 | 工作 | 资源/状态 | 为什么 |
|---|---|---|---|
| 1 | 全量同窗口解析：固定Unicode适配协议、失败策略、缓存和输入断言 | CPU可做，尚未全量执行 | 先去除正文/图范围混杂 |
| 2 | 实现无GNN EDU pooling及逐图关系类型控制，做小批前向/梯度检查 | CPU可做，尚未实现 | 区分切分聚合、关系类型和参数/优化作用 |
| 3 | 四条件×三种子CE机制实验 | GPU建议，未运行 | 对结构贡献作确认，而不是从域内融合反推 |
| 4 | 留域/留生成器，保持目标环境不参与选模 | GPU神经训练；协议CPU可做 | AI原文已失败，需先定位迁移来源而非只加humanized专家 |
| 5 | 有真实来源记录的同原文受控编辑强度测试 | 数据与来源记录为主 | 研究creator信号随编辑变化，而非让LLM猜身份 |

不建议继续在现有MixSet测试集上翻转分数、挑融合权重或选择“最好”的子域。新算法选择只在开发数据完成；若使用外部集适配，应重新定义train/dev/test并找新独立评测，不能仍称零样本迁移。

已有CE+TF-IDF Stacking可以保留为域内工程候选，不必部署parser；三模型Stacking可作为高成本互补对照，但两者都没有证明外部可靠。基础研究主线仍应是机制与泛化，而不是宣称新SOTA。
