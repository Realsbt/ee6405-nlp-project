# 文本—篇章自适应融合：改进实现与 GPU 实验

设计日期：2026-11-11；执行进度更新：2026-11-12。

## 这次做的是改进，不只是验证

个人模块建议命名：**面向文本来源检测的文本—篇章自适应融合模型**。

问题：现有 RACE 通过图 root 分类，而已有 EDU 对照对所有片段等权聚合。
本方案保留强文本表示，并学习哪些 EDU 值得作为补充；不使用关系标签或 GNN，
但仍依赖 EDU 切分，不能说完全摆脱了 parser。

```text
相同可见正文 → 同一个 RoBERTa
                 ├─ CLS 整体表示 ────────────────────┐
                 └─ EDU 内均值 → 注意力 → 篇章表示 → 门控 → 残差相加 → 分类
```

最终表示是 `CLS + gate * EDU_context`。门控初始约 0.119，让局部信息从较小补充开始。
这不是关系解析置信度，也不是 AI 作者概率。

## 已实现的四个条件

| 条件 | 用途 | 总参数 | 可训练参数 |
| --- | --- | ---: | ---: |
| `fusion_cls` | 匹配分类头的纯 CLS 基线 | 125,305,092 | 7,747,332 |
| `fusion_mean` | CLS + EDU 等权均值 | 125,305,092 | 7,747,332 |
| `fusion_attention` | CLS + EDU 注意力聚合 | 125,403,652 | 7,845,892 |
| `fusion_gated` | CLS + 门控 EDU 注意力聚合 | 125,405,189 | 7,847,429 |

门控版相对匹配基线增加 100,097 个参数。四组共享输入窗口、基础权重、分类头形状、
CE、采样规则和开发集选模规则。原 `text/graph/shuffled/edu` 四条件保持不变。

新 CLS 基线分类头与历史 RoBERTa 不同，不能直接冒充历史 91.15% 的模型。
模块效果与新 CLS 配对比较，最终性能表还需保留原 RoBERTa+SupCon 强参照。

## 接下来 GPU 应怎么用

1. 目标 GPU 先做四条件 smoke，确认数值和显存。
2. 固定种子 3407，训练四个条件，仅按开发集 Macro-F1 筛选；并列优先少参数。
3. 写下入选配置，冻结模型、损失、预算和比较对象，再补匹配基线与入选模型的
   42/2026 两个种子。总共四次筛选加四次确认训练。
4. 统一重载六个正式基线/入选 checkpoint，再评测试；报告逐种子差值、
   均值/样本标准差、四类表现、领域表现和资源成本。
5. 外部迁移需要新增兼容推理适配，本轮未实现，不能把已有旧模型的 MixSet
   结果挪作新融合模型的结果。外部集不参与选型。
